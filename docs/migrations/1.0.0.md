# Migrating from 0.2.1 to 1.0.0

1.0.0 is a breaking release. There is no codemod. Registration still uses `EmailsModule.forRoot()` with `type`, `key`, `SES`, and `MAILTRAP`. `forRootAsync({ useFactory, inject })` still works.

## Install the peers

`nodemailer` stays required. `@aws-sdk/client-ses` and `mailtrap` are no longer installed for you. Install the provider you send through. It is loaded on the first send that uses it.

```bash
npm install @saiuttej/nestjs-mailer nodemailer
npm install @aws-sdk/client-ses
npm install mailtrap
```

Node.js 20 or newer is required.

## Replace `body` with `text` and `html`

`emailData.body` is removed. Set `text`, `html`, or both. At least one is required. A string that used to go in `body` was sent as HTML. Put that string in `html`.

`send()` returns `{ messageId, provider, raw }`.

```ts
// 0.2.1
await this.emails.send({
  client: 'ses',
  emailData: {
    to: ['reader@example.com'],
    subject: 'Hello',
    body: '<p>Hello</p>',
  },
});

// 1.0.0
const result = await this.emails.send({
  client: 'ses',
  emailData: {
    to: ['reader@example.com'],
    subject: 'Hello',
    html: '<p>Hello</p>',
  },
});

console.log(result.messageId, result.provider);
```

## Add `type` to send options

Send options are a union. Set `type` to the client you are sending through. SES fields are the raw-email command fields except `RawMessage`, which this package still builds from `emailData`.

```ts
// 0.2.1
await this.emails.send({
  client: 'ses',
  emailData,
  options: { ConfigurationSetName: 'news' },
});

// 1.0.0
import { EmailClientTypes } from '@saiuttej/nestjs-mailer';

await this.emails.send({
  client: 'ses',
  emailData,
  options: {
    type: EmailClientTypes.SES,
    ConfigurationSetName: 'news',
  },
});
```

Mailtrap options need the same discriminator:

```ts
options: {
  type: EmailClientTypes.MAILTRAP,
  category: 'news',
  custom_variables: { userId: '1' },
  sandbox: true,
}
```

For the provider SDK's own client config and send fields, use the subpath helpers. An app that only imports `@saiuttej/nestjs-mailer` does not need both provider packages installed to type-check.

```ts
import { sesClient, sesSendOptions } from '@saiuttej/nestjs-mailer/ses';
import { mailtrapClient, mailtrapSendOptions } from '@saiuttej/nestjs-mailer/mailtrap';
```

`sesClient()` accepts `SESClientConfig` from `@aws-sdk/client-ses`. `mailtrapClient()` accepts the `mailtrap` client config. `sesSendOptions()` and `mailtrapSendOptions()` add `type` for you. Mailtrap template fields such as `templateUuid` are forwarded to the SDK.

## Catch the named errors

These cases used to throw a plain `Error`. Catch the class, or check `error.name`.

| 0.2.1 message                                            | 1.0.0 error                        |
| -------------------------------------------------------- | ---------------------------------- |
| `Duplicate email service client keys found: …`           | `DuplicateEmailClientKeyError`     |
| `Cannot have more than one default email service client` | `MultipleDefaultEmailClientsError` |
| `No default email service client found`                  | `NoDefaultEmailClientError`        |
| `Invalid email service client key: …`                    | `UnknownEmailClientKeyError`       |
| `Unable to find email service client`                    | `EmailClientTypeMismatchError`     |

Two checks are new. `InvalidEmailContentError` is thrown when the message has no sender, no recipient, a blank subject, or neither `text` nor `html`. `EmailProviderNotInstalledError` is thrown on send when `@aws-sdk/client-ses` or `mailtrap` is not installed. `EmailClientTypeMismatchError` is also thrown when `options.type` does not match the client used for that send.

## Addresses are copied

`send()` still trims, lowercases, and de-duplicates addresses. It copies them first, so the `emailData` object you pass in is left unchanged. Read your own copy if later code depended on the mutated addresses.

## Optional

These are new and do not require a rewrite.

- `isGlobal` on `forRoot` and `forRootAsync` defaults to `true`, which matches the old always-global module. Set `isGlobal: false` to keep the module local.
- `forRootAsync` also accepts `useClass` and `useExisting`. A class factory implements `create()`.
- One client may set `default: true`, as before. `send()` uses it when `client` is omitted.
